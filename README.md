# Groupme

多人、多次作业的自动分组工具。自由设置人数、每次组数和类型，选择混合组队或同类内组队，再比较「机会均衡」和「整体覆盖」，让同学尽量遇到更多不同队友。

**在线使用：[mappedinfo.github.io/groupme](https://mappedinfo.github.io/groupme/)**

## 使用

1. 设置总人数与作业次数。当前浏览器版本支持 6–300 人、1–30 次作业。
2. 每次作业的组数可以留空自动选择，也可分别指定，允许不同作业使用不同组数。
3. 如需考虑类型或水平，点击「编辑类型」逐人填写，或按编号每行粘贴一个标签，再选择「不同类型混合」或「同类型内组队」。默认不区分类型。
4. 点击「求解并比较两种方案」，查看两种目标的个人最低覆盖与全班不同搭档数。
5. 选择目标、作业和同学，查看每次分组、类型构成、新队友、已合作队友和个人合作历史。
6. 可填写姓名，或继续使用编号；复制按钮导出当前目标下的全部作业名单与类型。

## 分组约束

- 每次至少 **3 组**，不会出现只有 1 组或 2 组的安排。
- 每组至少 **2 人**，因此总人数至少为 6。
- 同一次作业中的组人数相差至多 **1**，只会出现一种或两种人数。
- N 人的每次组数可在 **3 到 floor(N/2)** 之间选择，没有额外的组数上限。
- 每人在每次作业中恰好进入一个组；各次作业可使用不同的组数。

自动模式可以选择各次组数。只以认识更多同学为目标时，较少的大组可能更有利。如果作业分工要求小组规模更小，请分别固定各次的组数。

## 类型与水平

标签由使用者填写，不根据姓名推断。每人一个标签，最多 20 个字符；空白归为「未分类」，并作为一种类型。标签按同学编号绑定，姓名可以重复。

- **不同类型混合**：每种类型在各组的数量相差至多 1。例如 6 位基础、8 位进阶分 3 组，每组有 2 位基础，进阶人数分别为 3、3、2。先满足这种均匀分散，再优化两种合作目标。并不要求每个组内各种类型的数量相等。
- **同类型内组队**：每个组只能包含一种类型；全体小组仍须满足每组至少 2 人、总共至少 3 组、全轮大小相差至多 1。单个类型不要求至少分 3 组。自动模式只搜索可行组数；指定组数不兼容时会列出可行组数。出现单人类型或任何组数都不可行时会说明原因。
- **不区分类型**：沿用原有分组规则，可提前保存标签。仅修改标签不会丢弃同样约束下已找到的更好方案。

同类模式的主要覆盖比例与个人未合作名单仅计算同类型伙伴，同时显示全班实际覆盖比例。混合模式显示全班覆盖比例；均匀类型规则可能让某些搭档无法同组，因此这个分母不代表所有搭档均可达到。所有类型均相同时，两个类型模式均等价于不区分类型。

类型编辑属于待求解设置；保存后需要重新求解才应用。旧结果继续使用原有类型快照，取消或失败不会用新标签重新标记旧结果。

## 两种优化目标

按顺序比较，前一项优先于后一项：

| 目标 | 第一优先 | 第二优先 | 平手时 |
| --- | --- | --- | --- |
| 机会均衡 | 提高认识同学最少者的不同队友数 | 增加全班不同搭档总数 | 缩小个人覆盖差异 |
| 整体覆盖 | 增加全班不同搭档总数 | 提高个人最低覆盖 | 缩小个人覆盖差异 |

不同搭档按无序人员对计数；个人覆盖差异使用不同队友数的平方差口径。重复碰面统计同一对人在第二次及之后同组的次数。求解不会把「重复最少」放在首位：一个大组可能同时带来旧队友和更多新队友。

两种搜索使用相同的限制，各自优先优化对应目标，并共同比较找到的可行候选。两种目标有时会得到相同结果。相同约束下再次求解，会保留每种目标已找到的更好方案；改变人数、次数、组数或类型限制后重新比较。

## 求解与最优性

计算在 Web Worker 中执行，页面可随时停止求解。每种目标使用约 4 秒的搜索预算，较简单的组合可能提前完成。求解采用多起点启发式搜索，同时考虑组数和成员安排，保留可复现的随机种子。

**有效分组不等于全局最优。** 只有达到可验证的数学界时，页面才显示「已证明覆盖目标最优」；否则显示「本次找到的最好方案 · 未证明全局最优」。这也意味着任意人数、次数和组数下不能一概保证零重复队友。证明针对覆盖与公平目标，不保证重复碰面次数在所有完全平手方案中也最小。

对 N 人、K 个均衡小组，令 q=floor(N/K)、r=N mod K，每轮合作名额为 K·q·(q−1)/2+r·q。因此不同搭档总数不超过全班人数对数与各轮合作名额总和的较小值。自动轮以合法组数中的最大合作名额计算安全上界。个人最低覆盖另受总名额与每轮可进入组大小的上界限制；这些上界不一定可达到。证明与统计都从实际分组重新计算，不信任浏览器存储中的派生指标。

同类模式使用各类型内部人数对数之和作为总覆盖上限。如果每人已经遇到其同类型的全部伙伴，则三层目标都已最优，即使不同类型人数导致个人覆盖数不同。固定 K 时，某类型 c 人的可行组数区间为 `[ceil(c/(q+1)), floor(c/q)]`；所有区间可以凑成 K，才满足全轮均衡要求。混合模式通过循环分配类型槽位构造始终可行的均匀分散安排，换人和重建各轮时保持该约束。

## 本地运行与验证

需要 Node.js 20 或更高版本，无需安装依赖。

```sh
npm start
npm test
```

默认地址为 `http://127.0.0.1:4173`，可用 `PORT` 调整。通过本地服务访问，不要直接打开文件。测试使用合成数据，覆盖分组约束、统计、输入错误与小规模独立最优值核对。

## 数据与部署

姓名、类型、设置和分组仅保存在当前浏览器，没有后端、分析脚本或第三方字体。升级会保留旧版可识别的姓名和组数。人数缩小时暂时保留额外姓名与类型，随后增大人数可继续使用。待求解的类型草稿与已求解结果分别保存。停止求解会保留原方案；浏览器拒绝复制时提供手动复制文本。

GitHub Pages 从 `main` 分支根目录发布，所有资源使用相对路径，无构建步骤。`.nojekyll` 关闭 Jekyll 处理。

发布涉及脚本或样式更新时，同步更新 HTML 入口、页面内核导入、Worker 地址与 Worker 内核导入的资源版本参数，避免浏览器把新页面与缓存的旧脚本混用。

- `src/grouping.js`：约束、求解、统计与最优性界。
- `src/solver-worker.js`：后台求解消息协议。
- `src/app.js`：两方案比较、输入、浏览器保存与复制。
- `src/style.css`：白底样式与手机布局。
- `tests/grouping.test.js`：内核回归与独立验证。
- `HANDOFF.md`：唯一当前状态入口。
